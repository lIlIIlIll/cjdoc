# 生成作者提供的中英文文档

构建 cjdoc 后，用独立 fixture 生成两种语言的静态页面：

```bash
target/release/bin/main generate --project tests/fixtures/projects/i18n \
  --format html --format markdown --format json --format coverage \
  --all-languages --output target/i18n-demo
```

打开 `target/i18n-demo/html/en/index.html` 或 `html/zh-CN/index.html`。英文 `add` 页面显示作者写的英文摘要、left 和返回值说明；right 保留中文原文并标记 `Original text: zh-CN`。这是特意保留的缺译样本，控制台会有 `CJDOC3108` 警告。

## 配置输入归属和发布集合

在项目的 `cjdoc.toml` 中声明未限定文字的语言和真正发布的语言：

```toml
[i18n]
default-language = "zh-CN"
languages = ["zh-CN", "en"]
missing-translation = "warn"
```

`default-language` 是输入元数据，启用 `[i18n]` 时必填。省略 `languages` 时只发布默认语言。输出语言由 `--locale zh-CN|en` 选择；CLI 的单语言默认值仍是 `zh-CN`。`--locale en` 不会改变未限定字段的归属。

首版支持 `zh-CN` 和 `en`，只规范化 ASCII 大小写。生成过程离线检查 RFC 5646 的 well-formed 语法及固定 grandfathered 列表，不查询语言注册表。`zh-Hans`、`zh-TW`、`en-US` 等不会作为别名使用。合法但不支持的语言会被拒绝。

`GenerationRequest.i18n` 覆盖根输入的配置。workspace 成员使用所属输入配置；缺少独立配置时使用 workspace 配置。路径依赖和缓存依赖使用自己的语言元数据，不继承根项目默认值。旧项目没有语言元数据时，文字的来源语言保持未知。

## 给同一字段写翻译

标签头使用紧邻、单行、无引号的 `@tag[lang=...]`：

```cangjie
/**
 * 计算两个整数的和。
 * @summary[lang=en] Adds two integers.
 * @param left 左侧数值。
 * @param[lang=en] left The left operand.
 * @param right 右侧数值。
 * @param[lang=en] right The right operand.
 * @return 两数之和。
 * @return[lang=en] The sum of the two operands.
 */
public func add(left: Int64, right: Int64): Int64 { left + right }
```

普通正文形成默认语言的隐式摘要和详细说明。也可以全部使用显式的 `@summary`、`@description`。仅有隐式摘要时，可以补显式详细说明；同一语言同一字段的重复定义会诊断，不会覆盖前一份文字。参数按源码声明顺序显示。

支持语言限定的字段包括 summary、description、param、return、throws、see、deprecated、example，以及 precondition、postcondition、invariant、performance、state、concurrency、platform、compatibility、error。since、version、author 保持共享元数据，不接受 `lang`。

限定只影响当前项。多段内容、列表、表格、引用、语义链接和围栏一直归属于当前项，直到下一个合法顶层标签。代码、列表、引用和行内代码里的伪标签保留为内容。没有启用新字段或语言配置的旧注释继续使用原有段落归属规则。

不支持裸 `[en]`、带引号的语言、分离的 `@param [lang=en]`、重复或未知属性，以及语言块指令。畸形已知标签会产生可定位诊断，并在下一个标签恢复。

## 处理重复条目和缺译

单值字段按声明、字段、真实参数及规范化语言关联。throws/see 只在目标唯一解析且每种语言只有一个候选时关联；行为契约按种类且每种语言唯一时关联。同一异常的多个条件、同种多条契约和独立示例不按标题、行号或数组顺序配对。无法证明关联时保留独立条目，并用 `CJDOC3107` 提示。

阅读选择是目标语言 → 所属输入默认语言 → 缺失。页面区分回退、空译文、冲突、缺失和未知来源语言。没有中文弃用原因时，英文弃用标签仍会使中文页显示弃用状态。未翻译的异常和契约不会消失。

无法证明跨语言关联的作者条目仍保留 `unpaired` 元数据和相关诊断。与当前阅读语言相同的条目直接显示正文，不展示“独立条目”技术标记；其他语言的原文仍提示来源语言。真实的缺译、回退、空译文和冲突提示不变。

这套模型记录作者文字和关联依据，不声称翻译忠实、同步或最新。独立示例不会借用同名示例的执行通过状态。自然语言 `lang=en` 不改变围栏的 `cangjie`、`cj`、`output` 等代码语言或执行指令。

## 单独检查翻译覆盖率

普通覆盖率和翻译覆盖率分别输出到 `coverage/coverage.json` 与 `coverage/translations.json`。翻译分母来自受众可见的真实签名、文档字段、原始独立条目及逻辑页面；回退、空文字、冲突、未知来源和未关联译文不算完成翻译。

配置阈值，或在检查命令中要求某语言达到 100%：

```toml
[coverage.translation]
en = 90
```

```bash
target/release/bin/main check --project . --require-language en
```

低于门槛会产生 `CJDOC3111` 和非零退出。`missing-translation = "deny"` 将缺译诊断升级为错误。`--require-language` 可重复；校验总是检查所有提供的变体，输出语言不会屏蔽错误参数或坏引用。

## 给指南和概述建立显式身份

翻译文件可以使用不同标题。用相同 id、不同 language 配对页面，用 sections 显式对应实际 Markdown 标题片段：

```toml
[[docs.pages]]
id = "start"
language = "zh-CN"
source = "docs/zh-CN/start.md"
route = "concepts/guides/start.html"
kind = "guide"
[docs.pages.sections]
usage = "开始使用"

[[docs.pages]]
id = "start"
language = "en"
source = "docs/en/start.md"
route = "concepts/guides/start.html"
[docs.pages.sections]
usage = "usage"
```

route 使用不带 URL 编码的相对 .html 路径，不含 scheme、查询或 fragment。显式设置 language 的页面必须提供 id；缺少 id 会产生 CJDOC3110 错误并省略该页面。kind 支持 project、package、module、guide；包概述可同时设置 package。没有可靠页面或章节映射时会诊断并降级到有效位置。不会根据翻译后的标题推断同一章节。

指南沿用 `cjdoc-bind` 的 qualifiedName 或 `id:` 目标；重载可使用 `selector="signature:public func ..."` 精确匹配源码头。绑定不从目录名称或翻译标题推断。已捕获的页面、树、来源和目标随 IR 保存，独立 `render` 不读取原项目目录。

## 渲染、组合和离线阅读

完整 `docs.json` 保留所有作者变体。可以复制该文件，脱离源码重新输出：

```bash
target/release/bin/main render --input target/i18n-demo/docs.json \
  --format html --format markdown --all-languages --output target/i18n-rendered
```

`--all-languages` 仅用于 `generate` 和 `render`，与显式 `--locale`、`--stdout`、旧的单页 Markdown 布局互斥。`serve` 使用 `--locale en` 或 `--locale zh-CN` 预览所选语言。语言树分别位于 `html/<language>/` 和 `markdown/<language>/`，完整 IR 和共享报告各输出一次。一次 generate 只运行一次源码/语义分析；热缓存仍保留所有语言输入，渲染阶段选择读取文字。

最终 `site-manifest.json` 列出实际存在的语言、页面、符号和章节目标。点击页头当前语言按钮（中文 / English）展开语言选项；Tab、Enter 可切换，Escape 关闭选项并返回按钮，点击外部也会关闭。原生展开控件和真实相对链接使无 JavaScript 时仍可切语言。有 JavaScript 时，深链使用显式映射保留参数、成员和指南章节；无法对应时提示回到同页开头。读者状态按项目、版本、语言和页面隔离。

发布清单的默认入口必须属于实际发布集合；仅发布英文时，该入口为 `en`，源文档的 `default-language` 仍可为 `zh-CN`。显式声明语言的指南也可独立使用：未配置 `[i18n]` 的旧源码仍保持语言归属未知，指南按各自 `language` 选择。

PocketKit 展示站只复制一次原生双语版本树，通过 `versions.json` 中的语言根定位页面。生成阶段的完整作者 IR 和中间目录不加入展示站；公开机器产物保留在各阅读根的 `machine/` 中，离线包与线上目录使用相同清单。

版本组合接收原生多语言输出根目录，也保留旧的单语言 HTML 输入：

```bash
target/release/bin/main versions compose \
  --version v1=target/docs-v1 --version v2=target/docs-v2 \
  --latest v2 --output target/versioned-docs
```

缺语言或符号时明确降级到该版本的默认语言、准确的 owner 或语言首页；不会跳到 latest 或用同名 API 顶替。Pages、离线包和本地 HTTP 子路径保持原 CSP，不使用远程翻译或 CDN。

## 公共 API 和格式迁移

```cangjie
import cjdoc.*
import cjdoc.model.*
import cjdoc.render.*

let request = GenerationRequest(".",
    astPreflightExecutable: Some("target/release/bin/main"),
    i18n: Some(DocumentationLanguageOptions("zh-CN", languages: ["zh-CN", "en"])))
let documentation = DocumentationEngine().generate(request)
let artifacts = renderDocumentationWithLanguageOptions(documentation, ["html"],
    LanguageRenderOptions(allLanguages: true))
```

Doc IR 当前为 v14；v6–v13 schema/golden 冻结，并严格迁移到 v14。独立的 `apiCollectionState` 在语言投影、离线重放和版本发布中保持 API 收集证据；严格高亮的展示错误不降低确定的删除分类。旧输入不获得猜测出的语言。搜索索引为 v9、API surface 为 v3、API diff 为 v2、doctest 为 v2、versions 为 v2；新增 translation-coverage/1 和 site-manifest/1。旧 API surface v1/v2 仍可比较，但不存在的语言证据保持未知。

完整作者 IR 可包含受众之外的声明，适合本地分析和后续受众投影。公开阅读索引、API 报告和 llms 内容先过滤受众；PocketKit 发布到 machine/docs.json 的 IR 也会过滤并经原生 decoder 验证。不要直接把本地完整作者 IR 当作公开阅读元数据。

验证入口和证据边界见 [验收记录](issue-64-acceptance.md)。
