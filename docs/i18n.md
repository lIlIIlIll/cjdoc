# 生成中英文文档

同一个库的中文注释可以同时服务中文和英文读者。`cjdoc` 不会自动翻译：译文由你在注释里逐字段提供，`cjdoc` 负责按语言发布、在缺译处回退原文，并把缺译和冲突报告出来。没有写译文的字段仍然显示默认语言原文，不会从页面上消失。

## 启用多语言

在项目根目录的 `cjdoc.toml` 中声明语言：

```toml
[i18n]
default-language = "zh-CN"
languages = ["zh-CN", "en"]
missing-translation = "warn"
```

- `default-language`：没有写 `lang` 的正文和标签属于这个语言。只要出现 `[i18n]`，它就必须填写。
- `languages`：实际发布的语言集合。省略时只发布默认语言；目前只支持 `zh-CN` 和 `en` 两种，最多登记两项。
- `missing-translation`：`warn`（默认）或缺译按错误处理（`deny`），见[处理缺译与回退](#处理缺译与回退)。

语言标签大小写不敏感：`zh-cn` 会规范化为 `zh-CN`，`EN` 会规范化为 `en`。但不会推断别名，`zh-Hans`、`zh-TW`、`en-US` 都按不支持的语言报错。

只发布英文也可以：把 `languages` 写成 `["en"]`，站点默认入口变成英文，未限定文字仍按 `default-language` 归属。

配置写错（缺少 `default-language`、出现未知键、语言不受支持）会在命令启动时失败，退出码为 2。没有 `[i18n]` 的项目中，旧注释仍按来源语言未知显示，普通字段不能使用 `[lang=...]`。例外是注释中含有顶层 `@note`、`@warning` 或 `@danger` 语法（包括该提示头的属性/正文错误），且没有普通完整多语言触发项时：它采用提示专用范围，允许提示使用语言标记，不要求默认语言，并保留未本地化的正文和其他标签。若启用了 `[i18n]` 或同一注释还使用普通本地化字段，则按完整多语言规则处理。

## 写译文

给标签加上紧邻的语言限定 `[lang=...]`，同一字段的其他语言写法放在同一条注释里：

~~~cangjie
/**
 * 计算两个整数的和。
 *
 * 溢出行为由编译选项决定。
 *
 * @summary[lang=en] Adds two integers.
 * @description[lang=en] Overflow behavior depends on compiler options.
 * @param left 左侧数值。
 * @param[lang=en] left The left operand.
 * @param right 右侧数值。
 * @param[lang=en] right The right operand.
 * @return 两数之和。
 * @return[lang=en] The sum of the two operands.
 * @throws IllegalArgumentException 任一参数为负数时抛出。
 * @throws[lang=en] IllegalArgumentException Thrown when either operand is negative.
 * @example 基本用法
 * ```cangjie
 * let sum = add(1, 2)
 * ```
 * @example[lang=en] Basic usage
 * ```cangjie
 * let sum = add(1, 2)
 * ```
 * @since 0.7.0
 * @author 文档组
 */
public func add(left: Int64, right: Int64): Int64 { left + right }
~~~

支持的字段：

| 字段 | 默认语言写法 | 译文写法 |
|---|---|---|
| 摘要 | 正文第一段，或 `@summary` | `@summary[lang=en] Adds two integers.` |
| 详细说明 | 正文后续段落，或 `@description` | `@description[lang=en] ...` |
| 参数 | `@param left 左侧数值。` | `@param[lang=en] left The left operand.` |
| 返回值 | `@return 两数之和。` | `@return[lang=en] The sum.` |
| 异常 | `@throws Exception 说明` | `@throws[lang=en] Exception 说明` |
| 相关引用 | `@see add 说明` | `@see[lang=en] add 说明` |
| 弃用 | `@deprecated 说明` | `@deprecated[lang=en] 说明` |
| 示例 | `@example 标题` 加代码块 | `@example[lang=en] 标题` 加代码块 |
| 行为契约 | `@precondition`、`@postcondition`、`@invariant`、`@performance`、`@state`、`@concurrency`、`@platform`、`@compatibility`、`@error` | 同名标签加 `[lang=en]` |

`@since`、`@version`、`@author`、`@group` 是所有语言共用的元数据，不接受语言限定；写成 `@since[lang=en]` 会报错 `CJDOC3112`。

写译文时注意：

- `[lang=...]` 必须紧跟在标签名后、写在同一行，不能有空格或引号：`@param[lang=en] left ...` 合法，`@param [lang=en]`、`@param[lang="en"]`、`@param[en]` 都会报错。
- 一个带 `lang` 的标签的多段内容、列表、表格、引用和代码围栏都属于该译文，直到下一个顶层标签为止。
- 代码围栏、列表和引用里的 `@param` 等文本只当作内容，不会被解析成标签。
- 语言限定只作用于自然语言文字；代码围栏的语言标记（`cangjie`、`output` 等）和 `@example` 指令仍按原样解析。
- 普通注释字段使用 `[lang=...]` 时，所属输入必须能确定默认语言（项目或该输入自己的 `cjdoc.toml` 中有 `[i18n]`），否则报 `CJDOC3105`。没有 `[i18n]` 时，只有提示专用范围中的 `@note`、`@warning`、`@danger` 可以使用 `[lang=...]`；若同一注释还触发普通字段本地化，则仍要求默认语言。

`@throws` 额外支持下文的 `id` 条目身份；它不是通用属性语法。其他未知或重复属性、语言块指令均不支持。

### 配对同一异常的不同条件

给同一异常条件的各语言说明设置相同 `id`，可以在异常类型没有唯一的本地符号绑定时仍安全配对：

```cangjie
/**
 * @throws[id=index-range] IllegalArgumentException `index` 小于 0 或不小于 `size`。
 * @throws[lang=en,id=index-range] IllegalArgumentException `index` is out of range.
 */
```

`id` 只在同一声明的 `@throws` 内有效，是 1–64 字节的 ASCII 标识符：首字母为 `a-z`，其余允许 `a-z`、`0-9`、`_`、`-`，大小写不折叠。只接受 `@throws[id=...]`、`@throws[lang=...,id=...]`，属性顺序固定；旧注释不必补写 `id`。

同一语言重复使用 ID，或跨语言 ID 指向不同的异常主体/可靠目标时，产生 `CJDOC3114` 错误，保留原文且不强行配对；畸形 ID 报 `CJDOC3113`。不要用异常类名、译文相似度或条目位置代替条目身份。

### 为提示正文配对语言

提示标签只接受小写 `@note`、`@warning`、`@danger`。属性格式为无属性、`[id=x]`、`[lang=en]` 或 `[lang=en,id=x]`；属性不加空格或引号，带语言与 ID 时顺序固定为 `lang` 在前。语言仅支持 `zh-CN`、`en`，接受大小写变体并规范化。ID 与异常条目的 ID 是不同的命名空间规则，但沿用相同的 1–64 ASCII 字节写法：首字符为小写字母，其余为小写字母、数字、`_` 或 `-`。

在启用 `[i18n]` 的完整范围中，可以用同一个 ID 配对同一级别的各语言正文：

```cangjie
/**
 * @warning[id=stale-cache] 缓存可能早于刚完成的更新。
 * @warning[lang=en,id=stale-cache] The cache may predate the latest update.
 */
```

下面两种写法分别展示冲突 ID 和无 ID 的独立语言文本：

~~~cangjie
/**
 * @warning[id=shared] 缓存可能早于刚完成的更新。
 * @danger[lang=en,id=shared] Do not use this cache.
 */
~~~

同一声明中跨等级重用 `shared` 会使两条提示都成为冲突的 `unpaired` 条目，并报告 `CJDOC3118`，不会把 warning 自动改成 danger。

~~~cangjie
/**
 * @note[lang=zh-CN] 使用前检查缓存时间戳。
 * @note[lang=en] Check the cache timestamp before use.
 */
~~~

没有 ID 的语言版本不会按位置配对；它们各自保留，也可能同时显示。

ID 作用于当前声明的三个提示等级共用的命名空间。相同 ID 在同一语言重复，或被不同提示等级共用，都会报 `CJDOC3118`；冲突正文仍保留为独立的 `unpaired` 条目，不选其中一个、不更换等级、不丢弃内容。同一个 ID 可在不同声明中重用。缺少 ID 的提示永不按位置、正文或“唯一候选”配对；多语言时每条提示都独立保留，并在适用时报告 `CJDOC3107`，不同语言的独立变体可能同时显示。

对有效且有 ID 的提示，阅读视图依次选择请求语言、输入的 `default-language`、唯一有效的其他语言。回退会标记实际正文语言，不算完成翻译。只有作者实际提供的非空目标语言文本才计为完整翻译，cjdoc 不自动翻译，也不依据正文措辞推断或提升风险等级。空正文报 `CJDOC3117`；若同一 ID 另有有效译文，可回退显示那段正文并标明空译。

正文只有 Markdown 引用定义、没有可见正文节点时也按空译处理。已配对条目保留 ID 和原文，使用相同的空译回退；无 ID 或身份冲突的条目不会借此重新配对。

没有 `[i18n]` 且一条注释含有顶层提示语法、又没有普通完整多语言触发项时，cjdoc 保存 `localizationScope = "admonitions"`：提示可以各自写 `[lang=zh-CN]`、`[lang=en]` 和可选 ID；普通摘要、描述、正文、参数和其他标签保持原样，不因它们没有语言限定而报 `CJDOC3105`。启用 `[i18n]` 或同一注释使用例如 `@param[lang=en]`、`@throws[id=...]`、`@summary`、`@description` 等普通本地化触发项时，范围为 `all`，沿用原有默认语言要求及完整字段选择规则。Doc IR 显式保存范围，不通过“当前有没有译文”猜测；JSON 仍保留所有作者语言变体。

属性结构或提示语法错误报 `CJDOC3115`，非法 ID 报 `CJDOC3116`；提示语言值格式错误或不受支持分别使用 `CJDOC3102`、`CJDOC3103`。这些错误头及其文字作为普通正文保留。受支持属性的完整示例及非提示写法见[使用手册](usage.md#写提示)。

## 处理缺译与回退

普通字段通常按“目标语言 → 所属输入的默认语言 → 缺失”选择。显式配对的 `@throws` 和有 ID 的提示在目标语言、默认语言都没有有效正文时，还可回退到唯一有效的其他语言作者文本，并标明实际来源语言；这不算翻译完成。读者看到的状态如下：

| 情况 | 读者看到 |
|---|---|
| 目标语言有译文 | 直接显示译文 |
| 目标语言缺该字段，默认语言有 | 显示默认语言原文，并标注“原文：zh-CN” |
| 目标语言字段为空（例如 `@param[lang=en] left` 后没写说明） | 回退显示原文，并标注“译文为空；原文：zh-CN” |
| 同一语言同一字段写了两遍 | 显示“译文冲突”，并用原文回退；不会用后一条覆盖前一条 |
| 只有其他语言写了该字段（例如只有英文弃用说明） | 显示“翻译缺失”；弃用等 API 事实仍保留 |
| 无法证明跨语言配对的条目 | 作为独立条目保留；非当前语言的条目标注“原文：<语言>” |
| 旧注释或页面没有语言信息 | 注释内容原样显示；页面在页首标注“语言未知” |

不会因为缺译而消失的内容：`@throws`、`@see` 和行为契约按默认语言回退显示；有 ID 且有效配对的提示也按目标语言和默认语言选择，并可回退到唯一有效的其他语言。弃用状态属于 API 本身，即使只有英文弃用说明，中文页仍会显示弃用状态，只在说明处提示翻译缺失。

多条 `@throws`、`@see`、行为契约和独立示例不按标题、行号或数组顺序配对。`@throws` 可用上述 `id` 配对；提示也只按显式 ID 配对。没有 ID 的提示始终独立；未指定 `id` 的 throws/see 只在目标唯一解析且每种语言只有一个候选时配对，行为契约按种类且每种语言唯一时配对。无法证明时保留独立条目并给出 `CJDOC3107`。

相关诊断：

| 场景 | 诊断码 | 级别 | 结果 |
|---|---|---|---|
| `[i18n]` 缺少 `default-language` | `CJDOC3105` | 配置错误 | 命令启动即失败，退出码 2 |
| 普通注释字段用了 `[lang=...]`，但所属输入没有默认语言 | `CJDOC3105` | error | 完整范围报错；仅提示范围不适用 |
| 普通标签的语言限定写法错误（多余空格、引号、缺少 `]` 等） | `CJDOC3101` | error | 该标签按语言限定失败处理 |
| 语言标签结构不合法（空值、`../en` 等） | `CJDOC3102` | error | 该标签不被采纳 |
| 语言不受支持（`fr`、`en-US` 等） | `CJDOC3103` | error | 该标签不被采纳 |
| 译文语言未列入当前输入的发布集合 | `CJDOC3104` | warning | 作者原文保留，但不发布该语言 |
| 同一语言同一字段重复定义 | `CJDOC3106` | error | 两处都标记为冲突 |
| 跨语言条目无法唯一配对 | `CJDOC3107` | warning | 保留为独立条目 |
| 缺译、回退、空译、冲突、未配对 | `CJDOC3108` | warning | `missing-translation = "deny"` 时升级为 error |
| `@param` 缺参数名或参数不存在；`@see`、`@throws` 目标无法唯一绑定 | `CJDOC3109` | error / warning | 参数类为 error，引用类为 warning |
| 指南页缺 id、同 id 同语言重复、章节映射失败 | `CJDOC3110` | error / warning | 前两种省略页面；章节映射失败省略该映射 |
| 翻译覆盖率低于门槛 | `CJDOC3111` | error | 命令退出码 1 |
| `@since`、`@version`、`@author`、`@group` 加了语言限定 | `CJDOC3112` | error | 语言限定被拒绝 |
| `@throws` 的条目 ID 写法错误 | `CJDOC3113` | error | 不按该 ID 配对 |
| 同一语言重复 ID，或跨语言 ID 指向不同异常条件 | `CJDOC3114` | error | 保留原文，不强行配对 |
| 提示属性结构或语法错误（语言值问题除外） | `CJDOC3115` | error | 无效提示头及其正文保留为普通正文 |
| 提示作者 ID 不合法 | `CJDOC3116` | error | 不按该 ID 配对 |
| 提示正文为空 | `CJDOC3117` | error | 不输出空提示框 |
| 提示 ID 在同一语言重复或跨提示等级复用 | `CJDOC3118` | error | 保留为未配对的独立提示 |

启用 `[i18n]` 后，每次生成文档都会为每个发布语言报告缺译（`CJDOC3108`），不需要额外开关。把 `missing-translation` 设为 `deny` 可以把这类诊断全部升级为 error。

## 配对指南页面

概念页和指南用 `[[docs.pages]]` 登记。同一逻辑页的不同语言版本用相同 `id`、不同 `language` 配对：

```toml
[i18n]
default-language = "zh-CN"
languages = ["zh-CN", "en"]

[[docs.pages]]
id = "start"
language = "zh-CN"
source = "docs/zh-CN/start.md"
route = "concepts/guides/start.html"
[docs.pages.sections]
usage = "开始使用"

[[docs.pages]]
id = "start"
language = "en"
source = "docs/en/start.md"
route = "concepts/guides/start.html"
[docs.pages.sections]
usage = "Usage"
```

两份 Markdown 可以使用不同标题和章节名：

```markdown
# 快速开始

## 开始使用

先安装仓颉 SDK，再安装 cjdoc。
```

```markdown
# Get started

## Usage

Install the Cangjie SDK first, then install cjdoc.
```

规则：

- 显式设置 `language` 的页面必须同时提供 `id`；缺少 `id` 会报 `CJDOC3110` error 并省略该页面。
- 同一 `id` 加同一 `language` 重复登记会报 `CJDOC3110` error。
- 同一 `id` 的不同语言版本是同一逻辑页的翻译；阅读时优先选择当前语言版本，没有时使用该 `id` 的默认语言版本并标注“原文：zh-CN”。两种版本都没有登记时，该页在这种语言下不出现。
- `route` 必须是 `concepts/` 下的安全相对路径，不能包含 scheme、`..`、查询串或 fragment；省略 `.html` 时自动补上，不同语言可以使用相同的 route。
- `[docs.pages.sections]` 的键是稳定的逻辑章节 ID，值是该语言 Markdown 中真实且唯一的标题文本；各语言可以写各自的标题。找不到标题或标题重复时会报 `CJDOC3110` warning，并省略该章节映射，页面其余内容保留。
- `title` 省略时取 Markdown 的第一个一级标题；`kind` 默认是 `guide`，也可以写 `project`、`package`、`module`。
- 指南可以把页面关联到 API：在 Markdown 里单独写一行 `<!-- cjdoc-bind target="my_package.add" -->`；同一语言有重载时再加 `selector="signature:public func add(left: Int64, right: Int64): Int64"`。每个语言版本各自写绑定，`cjdoc` 不会从目录名或标题推断。
- `[docs] index` 指定的项目首页只有一份，没有语言变体：其他语言阅读时显示同一份内容，并按语言来源标注“原文”或“语言未知”。

## 检查翻译覆盖率

用 `coverage` 格式生成报告：

```bash
cjdoc generate --project . --format coverage
```

配置了 `[i18n]` 时，除 `coverage/coverage.json` 和 `coverage/quality.json` 外还会写出 `target/doc/coverage/translations.json`，按发布语言列出翻译总数、已完成数、百分比，以及回退、缺失、空译、冲突、未知来源、未配对的数量和逐条状态。

统计口径：

- 分母来自当前受众可见的符号：摘要、参数（默认排除名字以 `_` 开头的参数，但有作者参数文档的 `_` 参数仍计入）、非 `Unit` 返回值、作者提供的其他字段（异常、引用、示例、弃用说明、行为契约），以及每个逻辑页面。
- 只有目标语言有完整作者文字（`complete`）才算完成翻译；回退、空译、冲突、未知来源和未配对都不算。

设置门槛：

```toml
[coverage.translation]
en = 90
```

取值 0..100，可以按发布语言分别设置，在生成文档时执行（`generate`、`check` 和 `serve` 的预览构建）。低于门槛会产生 `CJDOC3111` error，命令退出码为 1。

也可以在检查命令中要求某语言达到 100%：

```bash
cjdoc check --project . --require-language en
```

`--require-language` 可以重复，对每个给出的语言把门槛设为 100%；`render` 和 `diff` 不接受该选项。`--locale` 只选择阅读视图，不会隐藏其他语言的缺译或错误，所有发布变体都会被检查。

## 生成与阅读多语言站点

只读一种语言时用 `--locale`：

```bash
cjdoc generate --project . --format html --locale en
```

产物是单语言站点 `target/doc/html/index.html`，界面标签和译文都按英文选择，未翻译字段回退并标注“原文：zh-CN”。`--locale` 只接受 `zh-CN` 或 `en`，不传时默认 `zh-CN`。

一次生成全部语言用 `--all-languages`：

```bash
cjdoc generate --project . --format html --format markdown --format json --all-languages
```

输出目录按语言分开：

```text
target/doc/html/zh-CN/index.html
target/doc/html/en/index.html
target/doc/markdown/zh-CN/index.md
target/doc/markdown/en/index.md
target/doc/docs.json
```

语言目录之外的共享产物只写一份；其中 `docs.json` 仅在请求 `json` 格式时生成。`--all-languages` 只能用于 `generate` 和 `render` 的目录输出，不能和 `--locale`、`--stdout` 同时使用，并且要求项目配置了 `[i18n]`（否则报错）；`languages` 省略时只会输出默认语言目录。

本地预览所选语言：

```bash
cjdoc serve --project . --locale en
```

从已有 `docs.json` 重放（不重新扫描源码）：

```bash
cjdoc render --input target/doc/docs.json \
  --format html --all-languages --output target/rendered-docs
```

`docs.json` 保留全部作者变体，`render` 可以用 `--all-languages` 重新生成所有语言，也可以用 `--locale` 只重放一种语言。

阅读站点时，页头提供“中文 / English”切换；切换使用真实相对链接，没有 JavaScript 也可以工作。某个页面在目标语言不存在时跳到该语言首页；深链会尽量定位到同一页面的对应章节，找不到时回到页首。

## 发布与组合版本

发布时部署整个 `--all-languages` 输出目录即可：各语言分别在 `html/<语言>/` 和 `markdown/<语言>/` 下，共享产物在输出根。

多版本站点把每次生成的输出目录交给 `versions compose`：

```bash
cjdoc versions compose \
  --version v1=target/docs-v1 --version v2=target/docs-v2 \
  --latest v2 --output target/versioned-docs
```

多语言输出目录可以直接作为 `--version` 输入，语言和页面路由随版本保留；目标版本缺少对应语言的页面时会回到该版本的默认语言或语言首页，不会跨版本借用内容。其余选项见[高级用法](advanced-usage.md)。

## 限制

- 不自动翻译，也不检查译文是否正确、同步或最新。译文由你维护，`cjdoc` 只负责选择、回退和报告。
- `--check-examples` 会检查默认语言和译文中所有有效的 `@example`；带 `{run}` 指令的示例还会执行。语言条目处于 `invalid` 或 `conflict` 状态时不参与示例检查。
- 跨语言配对只依据显式信息：注释字段的语言限定、参数名、唯一解析的引用目标、提示作者 ID，以及指南页的 `id` + `language`。提示 ID 在同一声明内使用，三个提示等级共用命名空间；每个 ID 的同一语言只能出现一次，且不同语言只能在同一等级下配对。标题、目录名和条目顺序都不参与配对。
- 目前只支持中文和英文两种发布语言；语言标签不会做区域别名映射。
- 项目首页不属于语言的 `id` 配对，只有一份，各语言显示同一内容。
- 多包 workspace 中，每个输入读取自己的 `cjdoc.toml`；没有独立配置的 workspace 成员沿用根项目配置，路径依赖和缓存依赖使用自己的语言元数据，不继承根项目默认语言。
- 未配置 `[i18n]` 时普通注释字段没有翻译和回退标注；包含顶层提示语法且没有普通完整多语言触发项的注释可以使用提示专用范围，仅对提示本身做语言选择，普通正文与其他标签仍保持原样。
