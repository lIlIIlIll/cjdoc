# 编写 cjdoc API 注释

1. **选目标。** 用户点名时只改指定 API，先区分同名重载。没点名时，只补当前改动中对外的 API；无法确定目标时先列候选，不自行扩大范围。
2. **读实现和测试。** 确认真正的参数名、返回值、异常触发条件和边界行为。不猜契约，不改实现。
3. **写注释。** 沿用现有包与文档语言，把 `/** … */` 紧贴声明，首段写摘要。用声明里的真实参数名，说明非 `Unit` 返回值、实际抛出的异常及调用者需要知道的边界。写法见[随附参考](references/authoring.md)。项目已配置双语时，补齐目标字段的两种语言。示例中的 `output` 是作者写下的预期，不是实测结果。只有另获授权且信任项目示例代码时，才运行 `cjdoc check --project . --check-examples`。
4. **生成预览。** 在含 `cjpm.toml` 的项目或 workspace 根执行 `python3 <skill>/scripts/preview.py --project . TARGET [TARGET ...]`。将 `<skill>` 换成当前技能目录，目标用限定名；遇到重载，按候选签名选择对应的符号 ID 再查。
5. **打开返回的 API 详情页。** 对照实现核对签名、摘要、参数、返回值、异常和示例的预期输出。双语页逐字段确认是所需语言的正文，不是缺译回退。预览命令成功只说明检查和页面定位通过，不能证明注释写得对。
